Three-stage training

Train from the official Qwen3-VL model through Stages 1, 2 and 3. Each stage consumes the preceding stage's locally trained output. The downloadable GuidedNav model is the paper's final policy for inference and evaluation.

All commands run from GuidedNav/code/. Install the training environment and use the same absolute model and data paths on every node.

All stages use AdamW (betas=(0.9,0.999), weight decay 0.01, gradient clipping 1.0), cosine decay, 3% warmup, BF16, DeepSpeed ZeRO-2 and seed 42. Maximum sequence length is 8,192; image pixel bounds are 12,544–200,704. Stage 3 uses LoRA rank 32, alpha 16 and dropout 0. Its subtask, landmark, long-horizon spatial and local spatial loss weights are 0.01, 0.01, 0.5, 0.1, with 3% auxiliary warmup. Ground-truth annotations and the frozen VGGT teacher are used only during training.

Prepare the model and data

Download Qwen3-VL-8B-Instruct from its official model repository into a local directory, including tokenizer and processor files. This is the starting model for Stage 1.

Follow data preparation to prepare expert navigation examples, DAgger trajectories, the visual instruction mixture and guidance annotations. The paper uses approximately 0.53M R2R experts, 1.90M RxR experts, 2.97M DAgger examples and 0.79M visual instruction examples. Freeze the actual source files and selected rows in the training manifests before launching a run.

The public annotation add-on supplies the selected Stage 3 annotations, collected poses/actions and prompt metadata. It is not a replacement for the Stage 1 expert corpus, the Stage 2 DAgger corpus or upstream VQA media. Keep the same VQA selection across Stages 1 and 2.

Launch Stage 1 — expert navigation and visual instruction tuning

export GUIDEDNAV_START=/absolute/path/to/Qwen3-VL-8B-Instruct
export TRAIN_MANIFEST=/absolute/path/to/training/stage1/manifest.json
export TRAIN_OUTPUT=/absolute/path/to/runs/stage1
export MASTER_ADDR=10.0.0.1
export NNODES=4 NPROC_PER_NODE=8 NODE_RANK=0
bash scripts/train_stage1.sh

Run the same command on each node, setting NODE_RANK to its zero-based rank and keeping the rendezvous address and input/output paths consistent. The full-parameter output is TRAIN_OUTPUT/stage1-epoch1/.

Launch Stage 2 — DAgger navigation and visual instruction tuning

Collect and label navigation rollouts with your Stage 1 policy as described in data preparation. Use the DAgger manifest for this stage, together with the same visual instruction examples used by Stage 1.

export GUIDEDNAV_START=/absolute/path/to/runs/stage1/stage1-epoch1
export TRAIN_MANIFEST=/absolute/path/to/training/stage2/manifest.json
export TRAIN_OUTPUT=/absolute/path/to/runs/stage2
bash scripts/train_stage2.sh

The full-parameter output is TRAIN_OUTPUT/stage2-epoch1/. Stages 1 and 2 update the language model, vision tower and multimodal projector; they do not enable GuidedNav attention or spatial guidance.

Launch Stage 3 — GuidedNav guidance

Download the annotation add-on and the training-only VGGT teacher:

python tools/download_assets.py --group data
python tools/download_teacher.py --output ../assets/vggt/vggt.pt

Recover the official instruction text, render observations from the released poses and materialize the Stage 3 manifest following DATA.md. Validate decoded examples using your own Stage 2 processor:

export GUIDEDNAV_BASE=/absolute/path/to/runs/stage2/stage2-epoch1
export FULL_MANIFEST=/absolute/path/to/stage3-training-data/manifest.local.json
export FULL_OUTPUT_DIR=/absolute/path/to/runs/stage3
export PYTHONPATH="$PWD/src:$PWD/third_party/vggt"
python tools/smoke_dataset.py --manifest "$FULL_MANIFEST" --processor "$GUIDEDNAV_BASE"
bash scripts/train_stage3.sh

This stage starts fresh LoRA adapters, spatial projectors and a temporal gate on your Stage 2 backbone. It does not download or require an intermediate GuidedNav checkpoint. The exported adapter, processor, temporal state and recipe are saved together in FULL_OUTPUT_DIR/stage3-epoch1/. Keep that directory with the exact Stage 2 backbone used to train it.

Hardware and run checks

The default launch uses four nodes with eight GPUs each. Stages 1 and 2 use microbatch 2 and accumulation 4; Stage 3 uses microbatch 1 and accumulation 8. The scripts calculate accumulation from worker count to maintain global batch 256 and reject incompatible combinations. Set NNODES and NPROC_PER_NODE for your hardware; MICROBATCH can also be changed for Stages 1/2 (Stage 3 uses microbatch 1); matching global batch alone does not validate a new hardware/runtime configuration.

For a two-update diagnostic, use a separate empty output directory and set TRAIN_SMOKE=1 for Stages 1/2 or FULL_SMOKE=1 for Stage 3. A smoke run is not an epoch export or a reference-metric result. Complete trainer checkpoints preserve optimizer state for interrupted-run recovery; epoch exports are for stage handoff and inference.

Evaluate a model you trained

Use your own Stage 2 backbone and your own Stage 3 adapter together:

export GUIDEDNAV_BASE=/absolute/path/to/runs/stage2/stage2-epoch1
export GUIDEDNAV_MODEL=/absolute/path/to/runs/stage3/stage3-epoch1
export GUIDEDNAV_WEIGHTS_SOURCE=trained
export EVAL_OUTPUT=/absolute/path/to/new-results/r2r
bash scripts/evaluate.sh r2r

Replace r2r with rxr for RxR. To evaluate the downloaded paper model, leave the default released-model settings in place and follow the evaluation guide.

Validation scope

These launchers implement the paper's three-stage setup. The complete three-stage training sequence and GPU benchmarks have not been rerun from this public package. Recollected DAgger trajectories or newly selected upstream rows are new training data; they are not an exact reconstruction of the original frozen training corpus. The data guide identifies the released annotation selection and the inputs obtained or generated separately.
